# Development notes

How the parts fit, and the facts that are easy to get wrong. The README covers what the app does and how to build it.

## How the parts fit

- `NotchANC/App.swift`: menu, Sparkle, and `apply()`, which reacts to every UserDefaults change (keys `automatic`, `mediaVisibility`, `focusMinutes`, `focusStartShortcut`, `focusEndShortcut`, `shelf`, the three timer lengths in `Countdown.presetKeys`, one on/off key per `CardPart` (tiles and tabs), `menuBarIcon`, `hiddenDisplays`, `hideMenuBarIcon`, and per `PillMode` its `colorKey` hex and `iconKey` symbol). Reopening the app shows Settings.
- `NotchANC/Settings.swift`: the Settings window, a fixed-size `NavigationSplitView`: a sidebar of panes (General, Pill, Card, Focus, About) beside grouped SwiftUI forms that write UserDefaults directly. The card reads the same keys through `@AppStorage`, so a change shows at once.
- `NotchANC/Overlay.swift`: `PillLayout` (pure geometry, unit-tested) and one window per shown display. The window has the open card's size; only the pill view inside animates. Collapsed, the pill holds the playing app's icon (the state's icon with no track) and the visualizer, or a pause mark; without a cutout the track's text sits between and the bar hugs it. Hovering opens one card: status chips (Noise Cancellation on or off, or the headphones' other mode when the log names it; the output device and its volume), the player when a track is loaded, and a row of tiles. Three tabs at the right of the chips switch the card between that, the file shelf and the clipboard history; every opening starts on the first. The pill is black at the top and washed in the state's colour below. Hover uses mouse-moved event monitors. The window (a non-activating `NSPanel`) ignores clicks except while the pointer is on the pill, so right-click opens the status menu without stealing focus.
- `NotchANC/AudioTap.swift`: the visualizer's levels. A Core Audio process tap of the whole output feeds a private aggregate device; each 1024-sample block is split into five log bands, and each bar rests at half height on its band's running average. It runs only while a shown pill has something playing.
- `NotchANC/AudioOutput.swift`: the default output device's name, volume and whether it is headphones; the pill's output chip and the "With headphones" choice both read it.
- `NotchANC/Glance.swift`: the tiles' readings, taken only while a pill is open: headphone battery from `system_profiler SPBluetoothDataType -json` (no public API has it), the next calendar event from EventKit (asked for from the tile's own button, never at launch), and how busy the Mac is: processor load and memory from `host_statistics`, graphics load from the graphics driver's `PerformanceStatistics` entry in the I/O Registry (no public API has it), disk from the startup volume's capacity.
- `NotchANC/Countdown.swift`: the quick timer and the focus session, one countdown at a time, started from the card's Timer tile. While it runs the pill stays up and its right end shows the time left, in place of the visualizer if something is playing; at the end it plays a sound and shows a bell until the card is opened. A focus session also runs the Shortcuts picked in Settings (`/usr/bin/shortcuts run`) when it starts and when it ends, since macOS has no API to switch Focus.
- `NotchANC/Shelf.swift`: files parked on the pill, kept by path in UserDefaults; the files stay where they are. A drag that carries files opens the pill on the shelf tab (the hover monitors also watch drags), and the pill view takes the drop.
- `NotchANC/Clipboard.swift`: the last ten texts copied, in memory only. The pasteboard sends no change notice, so its counter is polled twice a second; contents marked concealed, transient or auto-generated (the nspasteboard.org markers password managers set) are never kept.
- `NotchANC/AirPodsMonitor.swift`: parses `bluetoothd` log lines (`LsnM <mode>` etc.) into a `ListeningMode`; no public API exists. Only Noise Cancellation turns the ANC pill on; the other modes are shown in the chip.
- `NotchANC/NowPlaying.swift`: MediaRemote refuses non-Apple processes since macOS 15.4, so a JXA loop in Apple's `/usr/bin/osascript` reads `MRNowPlayingRequest` and prints JSON lines. It runs for the app's lifetime: `AppDelegate.updatePill()` picks `PillMode.anc` (accent colour) when ANC is on, else `.media` (blue) when `MediaVisibility` says so: never, while something plays into headphones (the default; `AudioOutput`: Bluetooth transport or the jack's 'hdpn' data source), while something plays into any output, or always. It hides 2 s after playback stops.

## Facts that are easy to get wrong

- Notch and Dynamic Island (PROLED XDR MacBook Pro, Oct 2026) both report through `safeAreaInsets.top` and `auxiliaryTopLeft/RightArea`. ActivityKit and WidgetKit `DynamicIsland` are unavailable on macOS (27.2 SDK), so apps cannot draw inside the island. `cutoutName` guesses notch versus island by width, which only affects the menu label.
- Not sandboxed: the app must spawn `/usr/bin/log`. Hardened runtime is on, so reading the calendar needs the `personal-information.calendars` entitlement in `NotchANC/NotchANC.entitlements` as well as the usage text in `Info.plist`.
- SF Symbols are fine in the UI and menu bar, but not in the app icon (license). The icon is drawn in `tools/icon.swift`.
- Minimum macOS is 14.2, for the Core Audio process tap. Don't add `#available` branches.
- A MediaRemote command sent from osascript is dropped if osascript exits at once; `send()` waits half a second first.
- Clicking the player's track opens its app via osascript; for a browser it also selects the first tab whose title holds the track's title, since MediaRemote names only the app. Each browser family scripts tabs differently (`NowPlaying.tabFinders`); the bundle id is written into the script because a browser's terms resolve only at compile time.
- The player shows the playing app's icon, not the artwork: osascript reports the artwork's type and size but not its bytes.
- Never run the tests in a folder whose app was launched: macOS App Management then blocks writes into that signed bundle.
- Before a release, add the version's notes to `CHANGELOG.md`.
